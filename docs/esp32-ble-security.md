# Native BLE security

The pairing cryptographic toolbox, SMP feature-exchange core and lease-enforcing
session owner, host privacy resolver, P-256 math boundary and offline SC
Just Works/Numeric Comparison/passkey phase-two owner are implemented. See
[phase-two API and verification](esp32-ble-sc.md) and
[passkey/keypress support](esp32-ble-passkey.md). Remaining authentication
methods, controller encryption-key ownership,
persistent bonds and reconnection with saved keys remain unfinished under T139.
The owner is not connected to the radio transport yet. P-256 primitives now
provide wire-order public keys/key pairs and ECDH with pinned vendor math and an
explicit guarded entropy callback contract. See [P-256 API and verification](esp32-ble-p256.md).
These components alone
do not authenticate a connection or change GATT permissions.

`lib/net/smp-crypto.flex` provides allocation-free CMAC, Secure Connections
`f4`, `f5`, `f6`, `g2`, `h6`, `h7`, legacy `c1`/`s1`, wire-order AES `e` and
private-address hash `ah`. `smp_equal` compares fixed lengths without an early
exit on a mismatching octet. The definitions and sample data follow the
[Bluetooth Core Security Manager specification](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core-54/out/en/host/security-manager-specification.html)
and [RFC4493](https://www.rfc-editor.org/rfc/rfc4493).

Scalar input/output arrays use Bluetooth wire order, least significant octet
first. Address descriptors contain a type byte (public0/random1), followed by
six HCI-order address bytes. IO capability bytes and legacy seven-byte pairing
PDUs retain wire order. CMAC itself takes ordinary AES/CMAC octet strings.

| Function | Output bytes |
| --- | --- |
| `smp_cmac`, `smp_f4`, `smp_f6`, `smp_h6`, `smp_h7` | 16 |
| `smp_f5` | 32: MacKey followed by LTK |
| `smp_g2` | 4, little endian; application displays this integer modulo1000000 |
| `smp_c1`, `smp_s1`, `smp_e` | 16 |
| `smp_ah` | 3 |

The caller supplies valid input/output storage and disjoint512-byte scratch
storage. CMAC alone needs96 scratch bytes and accepts0..65535 message bytes.
Outputs may overlap inputs. Invalid extents/overlaps reject before modification;
AES errors leave outputs unchanged. Used scratch is cleared on success and
crypto failure. No entropy or P-256 key pairs are generated by these functions.

For either Xtensa chip, import `lib/platform/esp32-smp-crypto.flex` and call
`esp_smp_crypto_init(context, capacity)` with caller-owned256-byte storage aligned
to16 bytes. Deinitialize it with `esp_smp_crypto_deinit()`. Reserve this context exclusively until deinitialization; it must not overlap
scratch, inputs or outputs. The binding rejects ISR/concurrent calls,
out-of-range C pointers and direct AES argument/context aliases. Each AES
operation clears its full context and preserves the caller's interrupt state.
Errors include -19 before initialization, -16 for busy/ISR access and -22 for
invalid parameters; vendor errors retain their signed value.

AES comes from the pinned official Mbed TLS3.6.7 source archive. Its minimal
profile supports128-bit AES, uses a184-byte vendor context inside the256-byte
caller allocation, and prefixes every vendor symbol with `smp_vendor_`. This
keeps its implementation separate from the TLS library's broader AES profile.
No C application, Rust runtime or FreeRTOS is introduced.

```sh
"$FLEX" scripts/build-esp32-smp-crypto.flex -o build/build-smp-crypto
build/build-smp-crypto --archive /path/to/mbedtls-3.6.7.tar.bz2 \
  --output build/smp-aes --prefix /path/to/xtensa-esp32-elf-
```

For S3, add `--chip esp32s3` and use its toolchain prefix. The package contains
`libsmpcrypto.a`, its license and a source/profile/chip/ABI/hash manifest. Link the
archive with the ordinary `esp32-link --archive` option. The builder rejects
wrong source/chip inputs and output aliases before replacing existing outputs.

`lib/net/smp-pairing.flex` implements the LE feature-exchange phase for both
central and peripheral roles. It preserves the exact seven-byte request and
response for subsequent cryptographic checks. Association selection covers all
five IO capabilities, legacy/SC OOB rules, passkey roles and numeric comparison.
Key size, bonding and key distribution are negotiated with explicit minimum
security policies. Planned authentication is separate from verified link
security; the latter stays zero throughout this phase.

The caller serializes access in its host task and supplies aligned storage of
`sm_size(links)` bytes:256+1536 per connection, for one to four links. Initialize
with `sm_init(storage, capacity, links)`, then use
`sm_open(token, role, localAddress, peerAddress, config, nowMs)`. Role0 is central,
role1 peripheral. Each connection needs a strictly increasing positive token;
closing or reinitializing does not permit an old token to be reused. Addresses
are the actual connection addresses, in the seven-byte format described above.

The eight-byte config is IO capability, OOB flag, AuthReq, maximum key size,
initiator key distribution, responder key distribution, minimum key size and
policy. Policy bits1/2/4 require MITM/SC/bonding; bit8 attests that the supplied
OOB mechanism is secure; bit16 requests explicit application consent. Consent
accepts the feature plan only; it is not numeric-comparison authentication.
Non-SC local configs must not advertise LinkKey distribution. Unsupported peer
LinkKey bits are ignored without rewriting the received transcript.

Start central pairing with `sm_pair(token, nowMs)`; a peripheral can send a
Security Request with `sm_request_security(token, nowMs)`. Deliver complete SMP
PDUs to `sm_input(token, packet, size, nowMs)`:1 means consumed,0 ignored RFU,
2 requests a subsequent crypto-phase handoff, and -11 requires retaining the
input until queued output is acknowledged. Feature responses must be
acknowledged before that handoff. Pairing Failed and timeout cancel old output.

`sm_next_packet(token)` exposes the copied output through `sm_packet`,
`sm_packet_size` and `sm_packet_generation`. Acknowledge successful transport
acceptance with `sm_packet_sent(token, generation, nowMs)`. Event polling uses
`sm_next_event` and `sm_event_consumed(token, generation, kind)` with equivalent
generation checks. Events1..5 are features ready, consent requested, failure,
timeout and incoming Security Request. The last event asks the full pairing
owner to check existing bonds before deciding to pair. `sm_consent` also
requires the current generation. Views from another connection remain valid.

Call `sm_tick(nowMs)` with monotonic milliseconds even when no packets arrive.
The30-second transaction timeout locks that physical connection until close;
acknowledging output or receiving an unknown opcode does not extend it. Failure,
timeout and close clear reserved secret material. `sm_snapshot` copies224 bytes
of phase-one metadata without keys. Close every connection before `sm_deinit`.

`lib/net/smp-retry.flex` supplies the allocation-free repeated-attempt ledger
required by [Core5.4 Vol3 PartH2.3.6](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core-54/out/en/host/security-manager-specification.html).
Its owner must serialize calls and keep it alive across connection teardown.
`sr_init(storage, capacity, entries, minimumWait, maximumWait, decayPeriod, nowMs)`
requires aligned storage of `sr_size(entries)` bytes:128+64 per identity, for
one to32 identities. The minimum wait is1..3600000ms, maximum at least the
minimum and at most86400000ms, and decay period1..604800000ms. Time must remain
monotonic within the initialized instance, with headroom for those durations.

Admission keys are seven-byte canonical public/static identity descriptors or
the one tagged unresolved-peer bucket:kind2 followed by six zero bytes. Kind2
is internal metadata and must never be used as a cryptographic/HCI address. Raw
resolvable and nonresolvable private addresses are still rejected by the ledger.
The host privacy layer below selects an admission key; establishing trust in
a supplied bond view remains the full security owner's responsibility;
this module does not turn a received identity claim into a trusted bond.

`sr_begin(identity, nowMs)` returns a positive attempt lease. It rejects an
existing live attempt for the same identity with -16, an unexpired wait with
-11, and a full table with -105. Active identities and retained penalties cannot
be evicted to admit an unknown identity. `sr_wait(identity, nowMs)` reports the
remaining wait, but only a successful `sr_begin` authorizes an attempt.

Complete the exact lease with `sr_finish(lease, result, nowMs)`. Result1 covers
failure, timeout, abort and disconnect; result0 requires a fully verified
pairing, never just feature exchange. Each failure starts the minimum wait or
doubles the prior interval up to the configured cap. Each quiet decay period
halves its history toward the minimum and eventually forgets it; decay does not
shorten a wait already imposed. A successful pairing does not erase prior
failure history. Queries and denied attempts do not restart the wait. Closed
attempt leases cannot be reused, even after deinitialization/reinitialization.
`sr_deinit(nowMs)` refuses active attempts, waits or remaining penalty history.

`sr_export(out, capacity, nowMs)` writes exactly `sr_checkpoint_size()` bytes:
64+40 per configured entry. The canonical little-endian format contains policy,
lease-generation floor, identities, remaining durations and active-attempt
flags. `sr_import(input, size, nowMs)` accepts only an empty ledger with the
same capacity and policy. It validates the entire blob, including unused bytes,
duplicate identities, interval bounds and generation rollback, before mutation.
An interrupted attempt becomes a failure on restore. Saved remaining waits
restart conservatively without needing a trusted wall clock. Old attempt
leases remain invalid.

The codec provides neither authentication nor rollback protection. The pending
durable-storage adapter must authenticate the checkpoint, prevent rollback,
persist admission before processing pairing, persist completion and fail closed
on storage failure. The radio remains disconnected from this API until that
adapter and the remaining SMP phases are ready.

`lib/net/smp-session.flex` owns the feature engine and retry ledger together.
It requires both engines to be initialized, with no open feature-engine links
or orphaned retry leases, before `so_init(storage, capacity)`. Owner storage
needs `so_size(links)` bytes:64+64 per configured connection. All three storage
areas must be disjoint. Serialize calls in one host task; while attached, use
the owner entrypoints for session changes and keep the engines privately owned.

`so_open(token, role, localAddress, peerAddress, identity, config, nowMs)` copies
the admission key separately from the actual connection addresses. Its fifth
argument accepts a canonical identity or the internal unresolved-peer bucket. Opening
a physical connection does not begin a pairing attempt. `so_pair` and
`so_request_security` acquire admission before the feature engine can queue a
local start. Incoming Pairing Request and Security Request commands also require
admission before response or application decision. A Security Request and its
subsequent pairing reuse one lease. The lease stays live through consent,
feature completion and crypto handoff. Feature completion never claims verified
security or reports a pairing success to the ledger.

Use `so_input`, `so_consent`, `so_packet_sent`, `so_next_packet`, `so_next_event`
and `so_event_consumed` in place of their feature-engine equivalents. Existing
`sm_packet*` and `sm_event*` globals expose the copied packet/event views. Local
admission errors are returned directly. A peer start blocked by a wait or live
same-identity attempt receives Pairing Failed reason9; capacity/exhaustion uses
reason8. A retained outgoing failure packet must be acknowledged before another
start can acquire a lease. Malformed pairing starts that enter the procedure
are recorded as failed attempts. Wrong-role local API calls do not acquire one.

`so_tick(nowMs)` advances the protocol and reconciles all links. Call it
regularly even without traffic. Failure, consent rejection, timeout and
`so_close(token, nowMs)` finish the exact attempt as a failure once. Entry points
that take time also apply expired deadlines before proceeding; an API can
therefore return an error after reconciling a timeout. Closing an unrelated link
preserves other leases and their packet/event views. Deinitializing the owner
requires all links closed and preserves the separately initialized retry ledger.

When `so_input` returns2, the future crypto phase must call
`so_phase2(token, generation, lease, nowMs)` immediately before using the handoff.
It checks all three identifiers, feature-ready state, timeout and response ACK.
Report a crypto-phase failure with
`so_failure(token, generation, lease, reason, reply, nowMs)`; stale work cannot
cancel a newer attempt. There is no feature-only API that completes authenticated
pairing. The future phase-two/encryption owner must implement verified completion.

`so_snapshot(token, out, capacity)` copies256 bytes:the feature metadata224,
attempt lease at224, admission key7 at232, reserved zero at239, last
admission error at240 and owner time at248. It exposes no key material and its
verified-security field remains zero. Storage aliases are rejected. Unexpected
engine replacement or a foreign ledger lease latches an owner fault and stops
further session operations.

`lib/net/smp-privacy.flex` resolves actual connection addresses against an
immutable bond view and opens sessions through the admission owner. Address
classification and `ah` follow
[Core5.4 Vol6 PartB1.3.2](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core-54/out/en/low-energy-controller/link-layer-specification.html)
and [Vol3 PartC10.8.2](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core-54/out/en/host/generic-access-profile.html).
Static/NRPA random parts and RPA prand must contain both zero and one bits;
reserved random-address type10 is rejected. All descriptors retain HCI wire
order. RPA hash/prand octets are checked with the verified `smp_ah` helper.

Each32-byte view record contains identity7, flags1, IRK16 and eight reserved zero
bytes. Flag1 explicitly means IRK present; flag2 means the security owner has
verified the required saved-key reconnect. A pending identity keeps flag2 clear.
Duplicate canonical identities, reserved flags and orphaned key bytes are
rejected before crypto. An explicitly present all-zero IRK remains distinct
from an absent IRK. The caller owns and serializes the view; no record is
authenticated, promoted, serialized or modified by these helpers.

`sp_resolve(peer, records, count, out, work, capacity)` accepts0..32 records and
requires a32-byte output plus608-byte disjoint workspace. Public/static peer
addresses use direct lookup. RPAs are checked against every present IRK; an
ambiguous match returns -129. AES errors retain their signed status and leave
output unchanged. Started resolution clears all608 scratch bytes on exit;
parameter errors leave scratch/output unchanged. Outputs may not overlap peer,
view or workspace. No IRK is copied into the public result.

| Result offset | Meaning |
| --- | --- |
| 0..6 | Admission key:confirmed canonical identity or kind2+six zeros |
| 7 | Reserved zero |
| 8..14 | Matching candidate identity, or zeros |
| 15 | Status0 unknown,1 pending,2 recognized confirmed record |
| 16..23 | One-based record hint, or zero; valid only for this immutable view |
| 24..31 | Verified link security, always zero |

All unknown and pending peers share the unresolved bucket, including changing
public/static addresses, RPAs and NRPAs. This prevents unbonded address churn
from escaping retry penalties. A recognized confirmed identity uses its own
bucket. An IRK match only recognizes an identity claim; normal authentication
and encryption are still required before granting link/GATT security.

`sp_open(token, role, local, peer, records, count, config, work, capacity, nowMs)`
resolves and calls `so_open` under the same serialized view. Its workspace needs
640 bytes and is cleared after resolution starts, including failed view checks
and AES errors. Owner/configuration/address/capacity preflight runs before AES.
The session retains the actual local/peer addresses for the cryptographic
transcript and copies its admission key for that physical connection. Later
view changes do not silently reclassify a live link or change its attempt lease.

Before publishing a newly confirmed identity, use
`sp_inherit_identity(identity, 1, nowMs, work, capacity)` to copy unresolved
penalties into its canonical bucket. Before forgetting an identity, direction0
copies canonical penalties into the unresolved bucket. This helper needs16
scratch bytes and does not verify a reconnect or change the view. The full
security/storage owner must establish the saved-key evidence and commit the
view change only after successful inheritance. An active source/target lease
returns -16; table exhaustion returns -105 without evicting retained history.

The underlying `sr_inherit(sourceKey, targetKey, nowMs)` preserves source
history, lease-generation floor and the maximum interval, wait and decay
deadline. It never creates an active attempt. Quiet-history recycling follows
the ordinary ledger policy. Tagged buckets also survive checkpoint export,
restore and interrupted-attempt handling.
