Flexscript 0.0.4 adds signed compiler upgrades with a pinned Ed25519 public key.

- The tag-triggered release job signs the checksums for the full compiler and
  standalone core using an encrypted GitHub Actions private-key secret.
- Every release includes `SHA256SUMS.sig`, a detached Ed25519 signature bound
  to the release version, Linux x86-64 target, asset names and SHA-256 digests.
- `flex upgrade` requires that signature and verifies it against the public
  key hardcoded into the compiler before downloading or executing a candidate.
- Missing, malformed, corrupted, wrong-key and replayed signatures fail closed,
  leaving the installed compiler unchanged. There is no unsigned fallback.
- Signature verification runs in Flexscript through OpenSSL 3 C FFI, without
  invoking curl, a shell or the OpenSSL command-line tool.
- Bootstrap verification includes RFC 8032 Ed25519 vectors, non-canonical
  signature rejection, signing-policy checks and signed upgrade integration tests.

Target: Linux x86-64. The full compiler requires the glibc loader and libc;
HTTPS upgrades and signature verification also require OpenSSL 3
(`libssl.so.3`, `libcrypto.so.3`) and a trusted CA certificate store.
The standalone core can build the full compiler but cannot run foreign calls
or perform HTTPS upgrades itself. The original 0.0.1 binary still bootstraps
both compilers; the Rust seed remains frozen at 0.0.1.

The published 0.0.3 updater can install this release using its existing HTTPS
and checksum checks. That one-time transition does not enforce signatures
retroactively. Once 0.0.4 is installed, subsequent upgrades require signatures
from the pinned release key. Manual installation can verify this release's
signature first using a public key obtained from a trusted source.

Documentation: [release signing](https://github.com/J45k4/flexscript/blob/0.0.4/docs/signing.md),
[upgrades](https://github.com/J45k4/flexscript/blob/0.0.4/docs/upgrade.md), and
