# Software x86 guests

`emulator/x86/cpu.flex` combines a checked instruction interpreter with a native x86-64
block compiler written in Flexscript (`emulator/x86/jit.flex`).
`emulator/backends/software.flex` adapts it to the RAM and exit-buffer layout used by the KVM
monitor. It runs as a normal Linux process without `/dev/kvm` or QEMU.

```sh
build/flex-publish tools/flexvirt.flex -o build/flexvirt
build/flexvirt --backend software --demo
printf 'help\nexit\n' | build/flexvirt --backend software \
  --kernel workdir/flexos/build/flexos-baremetal.bin
```

## CPU and memory

Each VM owns registers, instruction pointer, flags, mode, CR0/CR3/CR4, EFER and
GDTR, IDTR and CR2. The decoder handles operand/address overrides, REX, ModR/M, SIB,
displacements and RIP-relative addressing. All guest memory transfers check
RAM bounds; cross-page writes validate the entire transfer before changing RAM.

The instruction subset covers the Flexscript compiler's integer kernel output:
moves, stack operations, arithmetic and logic, comparisons, conditional branches,
SETcc/CMOVcc, calls/returns, shifts/rotates, ADC/SBB, full-width signed/unsigned
multiplication and double-width division. CLC/STC/CMC modify carry alone in both
the interpreter and native translator. Boot support includes CLI, STI, CLD,
CR0/CR2/CR3/CR4 accesses, EFER and FS/GS base MSR accesses,
LGDT/LIDT/SGDT/SIDT, task-register load/store, far jumps/returns into
long mode, flat data segments, FS/GS overrides, SWAPGS, fences, prefetch hints,
CPUID, byte swaps, bit operations, REP MOVS and REP STOS. Single-vCPU atomic operations
include CMPXCHG, XADD and validated LOCK forms.
64-bit IRETQ can enter CPL3; SYSCALL/SYSRETQ use EFER.SCE and the guest
STAR/LSTAR/FMASK configuration. SYSCALL leaves stack switching and SWAPGS to
guest code. SYSENTER setup MSRs retain configuration, but SYSENTER/SYSEXIT
and compatibility-mode system calls are not implemented. VERR/VERW check
GDT segment access rights and update ZF. RDTSC splits the deterministic virtual
instruction clock (including idle time) into EDX:EAX without changing flags;
CR4.TSD prevents user access with #GP. TSC is not yet advertised as a Linux
clocksource, and RDTSCP/TSC MSRs are not implemented.
Locked CMPXCHG8B validates read/write access even when the comparison fails;
failure loads EDX:EAX and success commits ECX:EBX, with only ZF updated.
CPUID exposes a conservative Intel-compatible baseline and the separate
`FlexSoftVirt` hypervisor identity. This avoids the ISO linker's unknown-vendor
path, which skips leaf-1 feature discovery and rejects even baseline libc.
CET is unadvertised; ENDBR and disabled-CET RDSSP execute as no-ops.
Debug registers can be initialized and read; enabling hardware breakpoints or
debug traps reports an unsupported feature. SHLD/SHRD support 16/32/64-bit
operands and immediate/CL counts.

`emulator/x86/fpu.flex` owns each vCPU's x87 and XMM state. Whitelisted x87 and
SSE/SSE2 operations execute in W^X native helpers after complete operand
validation; host x87/XMM/MXCSR state is saved and restored. Supported state
operations include legacy environment/save images, FXSAVE/FXRSTOR and
LDMXCSR/STMXCSR. The writable MXCSR mask comes from the host FXSAVE image,
with the architectural `0xffbf` fallback when that image reports zero. This
supports DAZ on hosts whose SIMD unit implements it; reserved bits still raise
guest #GP before state changes. A native oracle compares DAZ/FTZ arithmetic,
status flags and save/restore in interpreter and JIT modes.
SSE2 PEXTRW/PINSRW support extended registers, all immediate values, zero
extension on extraction and bounded word-sized memory loads on insertion.
Native differential tests also cover ignored REX.W, unchanged flags and
faults that preserve the destination.
The block translator also handles 128-bit MOVUPS/MOVAPS, MOVUPD/MOVAPD and
MOVDQU/MOVDQA copies with integer host registers, avoiding per-instruction
FXSAVE/FXRSTOR. It preserves guest FP state and flags, checks CR0.EM/TS and
CR4.OSFXSR on every execution, checks aligned operands before accessing RAM,
and uses the checked memory helper for complete sixteen-byte transfers.
Cross-page operands fall back to the interpreter. Watched-code stores stop
the block before stale instructions execute. `tests/kvm/vector-copy.flex`
covers all register pairs, both modes, extended registers, memory, CPL3 paging,
RAM-end access, alignment and permission faults, cached control changes and
self-modifying code. Scalar MOVSS/MOVSD remain interpreted.
RCL/RCR support byte, word, dword and qword operands, register and memory
forms, CL/immediate/implicit counts and carry input. Only CF and single-count
OF change; other flags retain their values. Byte/word counts wrap through
nine/seventeen bits, and zero-count r32 results zero-extend. Memory operands
require write permission even at a zero effective count; the full operand is
validated before modification. Register dword/qword forms also enter native
blocks. `tests/kvm/rotate-carry.flex` checks 2,304 hardware-reference rows in
both engines, high/extended registers, count-register aliases and CPL3 memory
faults, including a cross-page transfer. The oracle checks native read-only
memory faults for zero and nonzero counts.
Multi-byte NOPs also enter native blocks without emitting a host memory
access. A bounded lookahead recognizes 66/CS and long-mode REX prefixes,
ModRM/SIB/displacement lengths and the fifteen-byte limit. It changes no
decoder state on failure. REX.B opcode 90 remains XCHG and uses the
interpreter; unrelated prefixed operations retain their previous handling.
`tests/kvm/nop.flex` covers both engines and modes, CPL0/CPL3, apparent
unmapped operands, register/flag preservation, page-boundary fallback,
invalid groups and overlong instructions. `nop-hardware.c` verifies fixed
NOP encodings against native hardware.
Register forms of F7 MUL/IMUL with 32-bit or 64-bit operands also enter
native blocks. Both product halves are written with architectural zero
extension for 32-bit results. Only CF/OF change; undefined status flags retain
the interpreter contract. Input aliases with RAX/RDX and extended registers
are loaded before either result is written. Memory, byte/word and division
forms retain the interpreter path. `tests/kvm/multiply-register.flex` checks
1,156 native hardware oracle rows in both engines, 32/64-bit modes, CPL0/CPL3,
register aliases, preserved registers/flags and actual native retirement.
Register forms of SSE2 PXOR, PCMPEQB, PMOVMSKB and PSHUFD also enter native
blocks. They retain SSE-enable checks and preserve flags, MXCSR and unrelated
guest registers. Two temporary host XMM registers are saved/restored around
each trusted instruction; these integer operations cannot raise arithmetic
SIMD exceptions. Memory forms remain interpreted. The native oracle and
`tests/kvm/vector-register.flex` check both engines, 32/64-bit modes, extended
registers, aliases, all shuffle immediates, zero-extension, cached control
changes and direct preservation of host XMM sentinels.
FXSAVE preserves its software-reserved tail and guest pointers
never contain host helper addresses. CPUID advertises FPU, FXSR, SSE and SSE2,
but the SSE2 instruction set is incomplete: unsupported forms fail visibly.
Integer/XMM MOVD/MOVQ, packed half-vector loads/stores and MOVMSKPS/MOVMSKPD/
PMOVMSKB support the early dynamic-linker paths. Transfer tests compare native
x86 results, exercise extended registers and verify exact memory widths and
upper-half clearing. Scalar CVTSI2SS/SD, CVT(T)SS/SD2SI and COMI/UCOMI
and scalar/packed SSE2 float-width and packed-integer conversions
use checked native templates with guest MXCSR, including signed 32/64-bit
integer operands, rounding/truncation, NaNs and arithmetic flags. The SSE oracle
compares 5,416 native cases in interpreter and JIT configurations.
Unmasked floating-point arithmetic is explicitly rejected pending precise
exception/commit handling. SSE3 and AVX are not advertised.
MMX uses the same per-vCPU x87 register image, checked operands and host-state
preservation. Packed integer operations, MOVD/MOVQ, shifts and EMMS have native
oracle coverage, including x87 stack aliasing and #UD/#NM/#MF checks.
Trusted x87/MMX/SSE helper templates share a bounded 128-entry cache, with a
separate W^X page per entry. Cache hits avoid rebuilding instructions or changing
page protection; collisions replace one idle entry. CPU reset preserves the
code cache while clearing guest FP state. Per-CPU ownership, collisions and
reuse are covered by tests. A local 200,000-instruction alternating PXOR/PADDQ
loop measured 0.493–0.504 s before caching and 0.084–0.085 s after, about 5.9x
faster for that loop; this is not an overall Linux/installer speed measurement.

Four-level paging supports 4 KiB, 2 MiB and 1 GiB mappings, canonical-address
checks, present bits, user/supervisor access at every table level and supervisor
write protection through CR0.WP. User writes require writable entries regardless
of CR0.WP. The current model omits complete reserved-bit validation,
accessed/dirty updates and NX enforcement. Unhandled faults stop the monitor
with a diagnostic and offending instruction address. Long-mode page faults
can enter a present ring-0 interrupt/trap gate without IST and return via IRETQ.
Events from CPL3 read RSP0 from the loaded 64-bit TSS and switch to the kernel
stack; implicit IDT/GDT/TSS accesses use supervisor permissions.
The guest receives CR2 and an error code, with the faulting instruction restarted
after its handler returns. INT3 delivers a no-error-code #BP trap with the following instruction address.
Floating-point disabled/lazy-state faults use #UD/#NM, and pending x87 exceptions
use #MF. Rings 1/2, IST and double-fault delivery remain unavailable.
Privileged instructions and port I/O above IOPL raise #GP; TSS I/O bitmap
permissions are not implemented. Unsupported MSR probes raise
#GP(0), so Linux can recover through its exception handler. Maskable interrupts
can enter ring-0 long-mode gates without IST, including from CPL3. STI and MOV SS delay interrupt
delivery through the following instruction; POPF and IRETQ can restore IF.
A four-entry read translation cache is
invalidated by writes to watched physical pages, paging-control changes, INVLPG
and RUN entry. Page-table walks watch their table pages; the JIT also watches
code pages. Ordinary data/stack writes preserve cached translations. A separate
instruction-fetch window shares this invalidation generation.
Direct memory helpers outside execution do not use cached translations. REP operations batch
up to 256 iterations while charging fuel per iteration and preserving completed
iterations if the next access faults.

IN/OUT yield KVM-compatible I/O exits to the shared device monitor. HLT terminates
the VM for Multiboot guests. For emulated Linux guests, HLT waits for an eligible
interrupt; a halt with interrupts disabled reports failure. Guest instructions are decoded and either interpreted or translated through
explicit native templates. Guest syscalls are never forwarded to the host. Software execution has a cumulative instruction budget, including each
REP iteration: 100 million steps by default, adjustable with `--fuel N`.

## Native execution and benchmarking

Both emulated backends default to `--cpu-engine jit`. `--cpu-engine interpreter`
keeps all execution in the interpreter; `--stats` prints total guest steps,
natively executed steps, native blocks and translation attempts. These options
apply only to emulated backends and are rejected for real KVM.

```sh
build/flexvirt --backend software --cpu-engine jit --stats --kernel KERNEL
build/flexvirt --backend software --cpu-engine interpreter --stats --kernel KERNEL
build/run-omarchy --fast-boot --stats
build/run-omarchy --fast-boot --cpu-engine interpreter --stats
build/flex-publish scripts/bench-x86.flex -o build/bench-x86
build/bench-x86 --iterations 2000000 --report build/x86-benchmark.json
```

The translator caches 32,768 bounded blocks in a per-CPU 128 MiB virtual code
arena, with about 8 MiB metadata, a physical-page watch bitmap and one helper
page. Code pages are populated as blocks compile. It compiles after four visits, at most
32 instructions/128 source bytes per block, entirely within one guest code page. Template expansion reserves room for a
complete final dispatch tail; emission can shorten a block at that limit.
It handles common 32/64-bit integer moves, ALU operations, register shifts/rotates,
NEG/NOT, register INC/DEC, BSWAP, BSF/BSR, CWDE/CDQE, LEA, branches,
conditional moves, loads/stores, MOVZX/MOVSX/MOVSXD and
stack calls/returns. Native 16-bit MOVs preserve the destination's upper bits;
byte MOV/CMP/TEST forms handle legacy high-byte registers and REX byte registers explicitly.
Immediate TEST and SETcc now have native register/memory paths. TEST r/m64,
imm32 sign-extends its constant in both engines. Hardware oracle tests cover
high-bit operands, all SETcc conditions, flag preservation, high-byte and
extended registers, precise faults and writes into translated code.
INC/DEC preserve CF. Bit scans update ZF, retain the interpreter's other flags
and preserve the entire destination on zero input.
Conditional moves validate and read memory sources even when the condition is
false. Native RDTSC preserves CR4.TSD privilege checks and uses the same
deterministic counter as the interpreter, including preceding instructions in
the current block. Extending loads
use the same checked memory helper and preserve guest flags. Stable cached
blocks chain natively.
Suitable register-only self-loops keep eight guest registers and arithmetic
flags on the host CPU across iterations, with a native fuel counter.
REP MOVS/STOS can use checked native chunks; overlap, direction, element width,
partial progress and instruction-budget accounting retain guest semantics.

Memory templates check RAM bounds and the same paging permissions as the
interpreter. A failed native access returns before modifying that instruction's
guest state; the interpreter retries it with precise page-fault recovery.
Ordinary data writes can continue within a block. Writes to watched physical
code/table pages invalidate its generation and return before the next guest
instruction. Native reads reuse the four-entry generation-tagged read cache;
direct memory calls bypass it, and privilege/control transitions invalidate it. Physical-page watches cover aliases. Code changes from the host
between RUN calls are detected by revalidating source bytes and mappings.

Only emitted templates and the audited helper execute as host instructions;
guest bytes are never copied into executable memory. Code pages change from
writable/non-executable to read-only/executable before use. The embedded helper
is checked byte-for-byte against `emulator/x86/jit-memory.S` by the test suite.
Unsupported instructions, cross-page accesses and unavailable executable
mappings use the interpreter. The CPU is still a single-vCPU experimental
subset, with the paging/privilege/device limitations described above.

The benchmark executes a matching integer loop on hardware, in the interpreter
and through the JIT. Only the final native RET versus guest HLT differs. It
reports the median of three execution samples, including cold block translation;
each native sample averages 100 runs. Initialization and guest image loading are
outside these loop timings. This measures a favorable CPU loop, not Linux boot,
full-system performance or actual KVM performance. `/dev/kvm` is unavailable on
the development host, so no measured KVM ratio is claimed.

Local results on 2026-10-11, with samples pinned to the same permitted host CPU:

| Workload | Original/interpreter | Native JIT | Direct hardware |
| --- | ---: | ---: | ---: |
| Integer loop, 2 million iterations / 8,000,004 guest steps | 2,421.85 ms | 1.32 ms | 0.544 ms |
| Omarchy predecompressed kernel to the 8254 failure | 71.08 s | 17.62 s | Unmeasured |

The loop uses medians of three samples: approximately 1,834x interpreter speed
and 41% native throughput. The emulated KVM API reaches the same boot stop in
17.27 seconds with identical serial output, diagnostics and native-step counts.
The boot comparison uses one complete process run
per version, including image loading, pinned to the same host CPU; it excludes
ISO checksumming/extraction and host decompression. The baseline executable was
saved before these optimizations. Boot serial output and final CPU diagnostics
match exactly at 172,873,905 guest steps; 144,729,173 steps execute natively.
These are local workload measurements, not general speed guarantees. Results
and logs are in ignored `build/x86-speed/`. FlexOS also boots and completes
`help`/`exit` with identical output in both CPU engines through both backends.

## Emulated KVM API

`emulator/backends/kvm-emulated.flex` implements the API subset used by our KVM library. Select
`--backend kvm-emulated`, or set `kvm_emulated_api=1` before creating a VM.
Device-open, ioctl, vCPU mapping and descriptor-close operations dispatch to the
test transport; guest RAM still uses an ordinary anonymous mapping. Fake
descriptors never reach Linux syscalls. KVM_RUN enters the same software CPU.

The accepted operations are API-version discovery, VM/vCPU creation, TSS
placement, one RAM slot, run-area sizing/mapping, the library's CPUID setup
sequence, GET/SET_SREGS, SET_REGS, RUN and close. The emulated CPUID list is empty;
guest CPUID reports a minimal integer CPU profile. The transport validates its accepted flat CPU
setup and rejects unsupported requests. It supports one VM session at a time;
close it before creating another. Do not change `kvm_emulated_api` while a KVM
handle is live.

Tests can set `kvme_fail_request` to an ioctl number and `kvme_fail_errno` to a
negative errno to fail that ioctl once. The suite uses this to verify cleanup
after each creation stage, CPU setup errors and RUN failures.

This tests userspace API sequencing and guest behavior through our KVM backend.
It cannot prove hardware KVM acceptance, CPU feature compatibility or kernel
ioctl validation. It does not create a device node or intercept system ioctls,
and it is not binary compatible with arbitrary KVM clients such as QEMU.

## Verification and scope

The [KVM suite](kvm.md) builds a native oracle executing ADD, ADC, SBB, SUB, CMP, AND, OR and
XOR at 8/16/32/64-bit widths over boundary-value pairs. Both interpreter and JIT configurations execute
the corresponding instructions and compares full register results and defined
status flags: 18,496 cases, including incoming carry. Another native oracle
compares 1,121 full-width MUL/IMUL/DIV/IDIV results and defined flags. Additional tests cover addressing, high-byte/REX
register selection, shifts, division faults, malformed prefixes, unsupported
instructions, fuel limits, cross-page transfers and non-identity/read-only/
unmapped pages, guest page-fault recovery and IRETQ. Linux loader tests verify
image bounds, setup data, E820, initramfs placement and the real 64-bit handoff
through both emulated backends. JIT differential tests cover 512 branch outcomes,
256 mixed programs, 256 register loops, 128 REP cases, exact fuel, self-modifying
code, code changes between RUN calls, memory bounds and paging permissions.
Compiled kernels exercise recursion, globals, memory, arithmetic
and the protected-mode to long-mode handoff through both emulated backends.

The existing FlexOS serial image was also verified locally through both paths:
boot banner, shell commands, RAM filesystem operations and guest halt.

This remains an incomplete x86 model. Nonflat legacy segmentation, other
privilege rings 1/2, AVX and interrupts beyond the subset above are
unavailable. The monitor has no BIOS/UEFI or network devices. Its storage devices
accept read-only media and separate writable regular-file VM disks. Linux
`--window` supplies a fixed boot framebuffer, rather than a virtual GPU.
PCI configuration mechanism #1 exposes a minimal host bridge at 00:00.0 for
Linux, allowing its type-1 configuration sanity check to pass. Only identity,
class and limited command bits are modeled; this is not a full chipset.
Multiboot guests retain the empty bus. Absent functions read as all ones.
Desktop/Doom and full Linux guests need further CPU/device support.

## Experimental Omarchy kernel boot

The monitor accepts a relocatable x86-64 bzImage using the documented Linux
64-bit boot protocol. It builds boot parameters, an E820 map, an identity-mapped
32-bit-to-64-bit trampoline and an optional initramfs. Linux guests default to
512 MiB RAM; `--memory-mib` accepts 64 through 3072 MiB. The Omarchy launcher
defaults to 2048 MiB. Boot payloads remain below 1 GiB, while E820 advertises all
guest RAM. An optional
`--uncompressed VMLINUX` loads an already-decompressed ELF from the same kernel,
validates its loadable segments against the bzImage workspace, clears BSS, and
uses its entry point. This avoids repeated decompression during CPU development;
it requires the matching bzImage for setup parameters. The ELF must come from
the same trusted kernel image; the loader does not authenticate their pairing.

```sh
build/flex-publish scripts/run-omarchy.flex -o build/run-omarchy
build/run-omarchy --prepare-only
build/run-omarchy
# Host-decompress the matching kernel to iterate faster on later CPU startup:
build/run-omarchy --fast-boot
# The same guest through the emulated KVM API:
build/run-omarchy --backend kvm-emulated
```

The helper downloads the official Omarchy 4.0.4 ISO into ignored
`build/omarchy/`, verifies SHA-256
`ddeded2758c48318d201dfdac905ecb28f570441883f0c052ea3cd5d05acf92d`,
and extracts `vmlinuz-linux-t2` and `initramfs-linux-t2.img`. Preparation needs
`curl`, `sha256sum` and `bsdtar`; `--fast-boot` also needs `zstd`. Execution uses our Flexscript software CPU with native block translation.
It never attaches host disks or runs the installer on the host.

The verified bzImage milestone is kernel serial output (`KASLR disabled: 'nokaslr' on
cmdline.`), guest demand-page handling, and progress into decompression.
The decompressed ELF also executes later kernel startup code in the higher-half
address space, including guest exception recovery and atomic operations. It emits Linux CPU
identification and ACPI discovery messages. There is no ACPI firmware table yet,
so Linux reports the missing RSDP. The original stop at `OUT 0x43, AL` has been
replaced by an 8254 timer, cascaded 8259 PIC and MC146818 RTC. Linux gets through
timer entropy collection, controller setup, interrupt enable and MSR probing.
With x87/FXSAVE/SSE support, Linux accepts the FPU and reaches PCI probing,
network initialization and `Trying to unpack rootfs image as initramfs...`.
The latest 2 GiB run unpacked the initramfs, executed `/init`, started
systemd-udevd and reached the Archiso startup hooks. The process
remains bounded by its instruction budget. With `--stats`, long runs report
progress and guest IP every 100 million steps, in addition to final statistics.
**The installer and desktop do not boot yet.** A read-only virtio block device
exposes the ISO with `--iso FILE`; Linux discovers its partitions, while Archiso
root mounting remains unverified. Installation, remaining floating-point and
CPU instructions, complete interrupt/privilege handling and desktop-compatible
graphics still need implementation. The helper defaults
to a 100-billion-instruction budget; serial output may pause during decompression.
Failures exit nonzero and include CPU registers and instruction bytes.

## PC timer and interrupt model

`emulator/pc/pit.flex` implements binary modes 0, 2, 3 and 4 on the three PIT channels,
byte sequencing, zero-as-65536 divisors, independent count/status latches,
read-back, gate control and channel-2 output at port 0x61. BCD and externally
triggered modes 1/5 fail explicitly. Channel 0 supplies IRQ0 rising edges.
`emulator/pc/pic.flex` implements cascaded, edge-triggered fixed-priority 8259s:
initialization, masks, IRR/ISR, nesting, specific/non-specific EOI, auto-EOI and
polling. Rotating priority, special masks and alternate cascade wiring fail.
The diagnostic/delay port 0x80 accepts byte writes.

`emulator/pc/uart.flex` provides COM1 with 16450 registers: DLAB divisors, scratch,
modem loopback, one-byte receive holding register, overrun status, prioritized
interrupt identification and transmit-empty acknowledgment. FIFO writes are
ignored and FIFO capability is not advertised. Host output completes
synchronously; this is not a baud-accurate UART. Host stdin feeds RX and IRQ4
through the PIC when OUT2 and the matching IER bit are enabled. Other standard
legacy UART slots read as absent. Linux autoconfiguration and userspace console
operation have separate verification gates: the actual Omarchy kernel detects
COM1 as a 16450 on IRQ4; userspace console operation remains unverified.

`emulator/pc/ps2.flex` provides an i8042 controller with command/status ports,
controller self-test, keyboard/AUX interface tests, AUX loopback, output-port
state and a bounded tagged output queue. Keyboard and mouse output raise IRQ1
and IRQ12 through the PIC. The keyboard supports identification, reset, LEDs,
typematic settings, scan enable/disable and raw set-2 make/release events.
The standard PS/2 mouse supports identification, reset, sample/resolution
settings, scaling, stream/remote/wrap modes and signed relative-motion packets.
The initial controller selects untranslated keyboard input, which Linux can
use directly. Translation, scan-code sets 1/3, active multiplexing and wheel
extensions are not implemented; unsupported modes are rejected explicitly.
Machine reset/A20 changes are not implemented. With `--window`, host keyboard
and relative mouse events connect to the event injection functions. Guest device probes pass through
both emulated backends. The actual Omarchy kernel registers the keyboard as
`AT Raw Set 2 keyboard`; Linux mouse detection remains under verification.

`emulator/pc/rtc.flex` provides CMOS ports 0x70/0x71, BCD/binary 24-hour calendar,
SET freeze, leap-year rollover, UIP, periodic/update interrupt flags and
clear-on-read register C. IRQ8 uses the slave PIC. It starts at the deterministic
date 2026-10-11 00:00 UTC. Alarm, daylight-saving and 12-hour modes fail explicitly.
There is no NMI delivery; the CMOS index retains the NMI-mask bit.

Emulated Linux execution yields a nonfaulting KVM_EXIT_INTR every 16,000 guest
instructions, including native chaining and REP, to poll devices. Virtual PIT
time advances one tick per 16 charged instructions, at a nominal 1,193,182 Hz.
While halted, the monitor advances this clock until an interrupt can wake the
CPU. Idle advancement has a separate cumulative bound equal to the selected
instruction budget, so an unwakeable interrupt-enabled guest cannot spin the
monitor forever. This is deterministic simulated time, not measured wall time or CPU cycles.
The original total instruction budget remains separate from each timeslice.
Real KVM uses host monotonic time for polled timer reads; IRQ injection/wakeup
on the hardware backend is not implemented or validated.

The suite checks counter latching and waveform boundaries, PIC nesting/cascade
and EOI, RTC rollover and flags, STI delay, interrupt frames and IRETQ, completion
of a pending IN before IRQ entry, and safe MSR #GP recovery in both CPU engines.
The end-to-end timer test delivers a PIT edge through the PIC into a guest IDT
handler. These tests do not prove Linux userspace or an installed desktop.

The full end-state requirements are tracked in [Omarchy boot](omarchy-boot.md).

Linux interfaces: [boot protocol](https://docs.kernel.org/arch/x86/boot.html),
[boot parameters](https://docs.kernel.org/arch/x86/zero-page.html), and
[decompressor demand paging](https://github.com/torvalds/linux/blob/master/arch/x86/boot/compressed/ident_map_64.c).

Architecture references: [Intel instruction-set manuals](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html),
[AMD64 system programming manual](https://docs.amd.com/v/u/en-US/24593_3.44_APM_Vol2),
and [Linux KVM API](https://docs.kernel.org/virt/kvm/api.html).

## Native Linux display window

`--window` (emulated Linux backends only) reserves the top 4 MiB of RAM from
E820 usable memory and passes a 1024x768 XBGR8888 linear framebuffer through
Linux `screen_info`. The native SDL2 window uploads guest pixels with opaque
host alpha, preserving the guest buffer. It connects physical keyboard codes
and relative mouse events to the i8042 model, queues input when the controller
is busy and releases held keys on focus loss. Closing the window stops the VM.

`tests/kvm/framebuffer.flex` verifies boot fields, reservation and CPU pixel
stores through interpreter/JIT. `tests/kvm/window.flex` additionally checks
SDL pixel readback and keyboard mapping; it requires SDL2 and can run with
`SDL_VIDEODRIVER=dummy SDL_RENDER_DRIVER=software`. Native window presentation
was also exercised. The official Linux kernel separately rendered boot text in
the native window through simpledrm and the framebuffer console. An installer
and a working Hyprland desktop remain unverified.

## Installation media and VM disk

`--iso FILE` attaches a regular file through a legacy virtio PCI block device at
00:01.0 (1af4:1001, subsystem device 2). BAR0 defaults to I/O 0xc000, with a
64-byte allocation and an INTx line on IRQ11. Linux guests connect this line to
the PIC. Queue zero has 128 descriptors and 4096-byte ring alignment; indirect
descriptors and event-index suppression are not advertised. The device offers
the read-only feature and reports capacity in 512-byte sectors.
`--disk FILE` attaches a separate writable regular file at 00:02.0, I/O 0xc040
and IRQ10. This device offers FLUSH rather than RO; writes use bounded `pwrite`
and successful flush requests call `fsync`.

Reads use bounded guest-physical scatter/gather buffers and host `pread`, with
all chain bounds and metadata overlap checked before DMA. Cycles, unsupported
flags, queue overruns and malformed DMA fail explicitly. Out-of-capacity reads
and writes to read-only media receive IOERR; other unsupported request types
receive UNSUPP. GET_ID
is supported. Files must be regular, sector-aligned files of at most 1 TiB.
The ISO is opened read-only. Writable backing files are opened without following
symlinks and are never truncated by the monitor. No host block devices are
exposed. The Omarchy launcher creates a 64 GiB sparse `build/omarchy/disk.img`
exclusively if absent, preserving an existing disk; `--disk FILE` overrides it.
The monitor invalidates CPU mapping/code caches after device DMA.

`tests/kvm/virtio-blk.flex` covers device registers, bounds, read data, status,
interrupt suppression, reset and 16-bit ring wrap. `virtio-probe.flex` exercises
PCI discovery and an actual guest sector read through both emulated backends.
The actual Omarchy kernel has bound virtio_blk and discovered the ISO as `vda`
with two partitions. Archiso mounting and actual installation remain unverified.
Writable-file tests also verify writes, flushes and persisted data after close
and reopen; guest I/O probes exercise simultaneous media and disk devices.

## User-mode CPU verification

`tests/kvm/user-mode.flex` exercises a kernel IRETQ into user code, a guest
SYSCALL/SYSRETQ round trip, interrupt entry through TSS RSP0 and return to the
user stack. It also checks a supervisor-page access fault from user code,
#GP recovery from user CLI, permissions at upper paging levels, read-only user
write rejection with CR0.WP clear, and privileged instruction rejection. Both
interpreter and JIT configurations run the test. CPL3 blocks can now execute
natively. The native walker enforces user access at every paging level and
read-only user mappings even with CR0.WP clear; tests cover large pages and
permission changes across privilege transitions. Real Linux userspace has also
started systemd-udevd and reached the Archiso initramfs hooks. Installation and
the installer screen remain unverified.

Accumulator immediate ADD/OR/ADC/SBB/AND/SUB/XOR/CMP encodings with 32/64-bit
operands now use native register ALU execution. REX.W immediates are signed
imm32; 32-bit writes clear the high half, while CMP preserves the entire
accumulator. Guest carry and non-arithmetic flags retain the existing ALU
contract. Byte/word forms fall back. `tests/kvm/accumulator-immediate.flex`
checks boundary values, carry inputs, all general registers, flags, privilege
levels, CPU modes and native retirement against the established interpreter
ALU. `scripts/bench-accumulator-immediate.flex` measures the isolated path.

Native long-mode memory operands can now begin with an FS or GS override.
Address generation loads the guest base at execution time, before the normal
checked memory helper and SSE alignment checks. LEA and implicit stack
addresses ignore the override. Other prefix orders and legacy FS/GS execution
retain their prior interpreter behavior. `tests/kvm/segment-native.flex` covers
324 differential cases across 27 instructions, both segments, alignment,
CPL3 paging, permissions and RAM boundaries, plus cached-block base changes
and legacy-mode fallback. `scripts/bench-segment-memory.flex` exercises the
FS-relative ADD pattern sampled in the actual guest.

Native SSE2 register translation now also handles PADDQ and PSRLDQ (0F 73 /3).
PSRLDQ uses the ModRM r/m destination and an unsigned imm8; counts above 15
zero the result. It retains existing SSE enablement guards and host XMM0/1
save/restore. Memory and other 0F 73 groups retain interpreter execution.
The expanded vector-register oracle and differential suite cover 4,352 rows,
including every immediate, aliases, high registers and host XMM preservation.
